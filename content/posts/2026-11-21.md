### Your $30k GPU Is Waiting on a Shared Xeon

**来源：** Medium（Roan Brasil Monteiro） ｜ **时间：** **2026-11-20T13:24:51Z**（= 11-20 21:24 CST）✅ verified live

文章以实测数据指出，宿主 CPU 是当前推理栈的隐性瓶颈：vLLM、SGLang 的调度器跑在宿主 Python 上，每步解码都要回控 CPU；一旦宿主 CPU 被争用，最贵的 GPU 会被最便宜的部件拖垮。

[原文链接 →](https://medium.com/@roanmonteiro/your-30k-gpu-is-waiting-on-a-shared-xeon-1b151389b8e0)

补充细节（均来自上述文章原文，verified live）：

- Blink 的做法是把推理栈整体搬离宿主 CPU：SmartNIC 处理请求，一个永不退出的 CUDA 内核负责调度。

- 同卡、同模型、同流量下，仅因 CPU 上跑了 pbzip2 争用，vLLM 在 H100 上跑 Llama-3 8B 的吞吐就从 7,475 tok/s 跌至 1,961 tok/s，P99 首 token 延迟从 150ms 升至近 21 秒。

- 注意：Blink 论文本身发表于 2026 年 4 月（arXiv:2604.07609），新的是这篇分析文章，不是论文。

### Release v1.3.0 · NVIDIA/TensorRT-LLM

**来源：** GitHub（官方发布页，一手） ｜ **时间：** **2026-11-20（日期已验证，具体时刻未在发布页文本中显示）** ⚠️ 时刻未验证

TensorRT-LLM 1.3.0 破坏性移除 TensorRT 引擎后端（PyTorch 成为唯一后端、trtllm-build 消失），新增 Anthropic Messages API、Rubin (SM107) 预览、DeepSeek-V4/Kimi K3/Qwen3.5 支持、KV Cache Manager V2 与 KV 压缩、DWDP/Helix 并行及分离式推理，升级前必须看迁移指南。

[原文链接 →](https://github.com/NVIDIA/TensorRT-LLM/releases/tag/v1.3.0)

补充细节（均来自上述 GitHub 发布页原文，此前已验证）：

- KV Cache：Manager V2 按模型默认启用；新增 TriAttention 与 NVFP4 冷页压缩、NVFP4 KV cache 与磁盘缓存、FlexKV 与 LMCache 连接器、逐对话块复用。

- 并行与 MoE：新增 DWDP（分布式权重数据并行）、扩展 Helix 上下文并行、KV cache 感知的 attention-DP 路由器、NCCL-EP 后端、最多 2048 专家。

- 推测解码：新增 DSpark、DFlash、Suffix Automaton、PARD 草稿器与 EAGLE3 动态树。

- 量化：新增 MXFP8 (W8A8) 线性与 MoE、经 Marlin 的 W4A16 NVFP4 weight-only（可在 Hopper/Ada 上跑 NVFP4 检查点）。

本类别其他检查结果：vLLM（v0.34.0 为 11-18 发布）与 SGLang（最新 v0.5.23 为 11-02）本窗口均无新版本；Wally 推理周报的日期无法核实，未计入。
